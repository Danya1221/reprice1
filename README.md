# reprice1

Telegram-бот для чтения прайса поставщика и публикации собственного прайса с наценкой.
Поставщик читается пользовательским аккаунтом Telethon. Необязательный BOT_TOKEN
создаёт отдельный интерфейс управления; аккаунт оператора может отличаться от аккаунта,
которому доступны прайсы.

## Что исправлено

- Ответ собирается из новых и отредактированных сообщений после запроса. Старое меню
  не считается свежим прайсом. Поддерживаются ответы из нескольких частей.
- Кнопки поставщика распознаются без учёта регистра и декоративных эмодзи.
- Разбираются текстовые сообщения, TXT, CSV и XLSX с товаром и ценой в одной строке.
  Из документов извлекается текст; PDF, картинки и произвольные сложные таблицы требуют
  отдельного адаптера и не публикуются как будто это распознанный прайс.
- iPhone разделяется по моделям и явно указанному SIM/eSIM. Сохраняются флаги, память,
  цвет, CPO, «Актив», «Ориг. Упаковка» и прочие пометки в названии. Страна не используется
  для угадывания типа SIM. Samsung сохраняет «+» и флаги, технические SM-коды убираются.
- Ray-Ban Meta, LEGO, Dyson, Canon, DJI/Insta360, Kodak/Fujifilm, Google, B&W и другие
  известные бренды получают свои блоки. Ray-Ban S50 → M, S53 → L. Неизвестные строки
  доступны для проверки через /rejected; бот не выдаёт их за правильно разобранные.
- Названия оформлены как code для копирования средствами Telegram. Наценка применяется
  к исходной цене при каждом расчёте и не накапливается. Валюты не конвертируются.
- Длинные блоки делятся на страницы в пределах лимита Telegram. Обновляются сохранённые
  сообщения; запрет редактирования не вызывает отправку дубля.
- Удалённый пост восстанавливается даже при неизменившейся цене. После потери ответа на
  отправку бот сначала ищет созданный пост. Старый target_message_id используется при миграции.
- При ошибке одного источника сохраняется предыдущий полный прайс. Источник 1 имеет
  приоритет над источником 2 для одинаковых товаров; страна, состояние и SIM не смешиваются.
- По умолчанию с 20:00 до 10:00 МСК цены скрыты, запросы поставщикам не отправляются.
  Днём цены скрываются, когда все настроенные поставщики явно закрыты.
  Если один из двух поставщиков открыт, используются его товары.
- Стоп, настройки и ID сообщений сохраняются атомарно. Повреждённый state.json вызывает
  понятную ошибку вместо сброса и массовой повторной публикации.
- Исправлена ошибка HTML-страницы авторизации из-за фигурных скобок CSS, добавлены защита
  формы, корректная работа с 2FA и отключение клиента после получения сессии.

## Запуск на Railway без терминала

1. Подключи репозиторий к сервису Railway. Dockerfile и команда запуска уже включены.
2. В Variables укажи API_ID, API_HASH, SESSION_STRING, SUPPLIER_BOT, TARGET_CHANNEL.
   API_ID/API_HASH относятся к Telegram API, а не к токену BotFather.
3. Аккаунт SESSION_STRING должен иметь доступ к поставщику и быть администратором
   целевого канала с правами отправки, редактирования и удаления собственных постов.
   Используй @username, ссылку https://t.me/username или числовой ID вида -100….
4. Для цепочки «Прайс → Актуальный прайс»:
   REQUEST_TEXT=/start и BUTTON_PATH=Прайс > Актуальный прайс.
   Если поставщик сразу отвечает на /prices, поставь REQUEST_TEXT=/prices и очисти BUTTON_PATH.
   Для готовой ленты поставь SOURCE_MODE=feed — команды в неё не отправляются.
5. Добавь Volume с точкой подключения /data и STATE_FILE=/data/state.json.
   Одна реплика. Для SESSION_STRING не должно быть другого активного экземпляра на другом хосте.
   Перед первой заменой старого сервиса перенеси прежний state.json на Volume, если он сохранился.
6. Для кнопок управления добавь BOT_TOKEN от BotFather. В ADMIN_IDS укажи свой числовой
   Telegram user ID; несколько ID разделяются запятой. Если поле пустое, управлять сможет
   только владелец SESSION_STRING. Открой управляющего бота и отправь /start.
7. Нажми Deploy. Признак готовности в логе: «reprice1 запущен».
   Проверь /status, затем /sync и первые опубликованные блоки.

При переходе со старой версии реальные Variables сохраняются. Новые переменные необязательны.
Наценка по умолчанию 0. Режим ночного скрытия включён; при другой схеме работы его можно
отключить через OFF_HOURS_ENABLED=false.

## Получение SESSION_STRING через браузер

1. Укажи API_ID, API_HASH, SETUP_MODE=true и случайный секретный SETUP_KEY.
2. В Railway Networking включи публичный домен сервиса и открой его.
3. Введи SETUP_KEY и номер Telegram, затем код и, если запрошен, облачный пароль 2FA.
4. Скопируй полученную SESSION_STRING в Variables.
5. Поставь SETUP_MODE=false, удали SETUP_KEY и выполни Redeploy.

Сессия выводится только в защищённой форме. Её нельзя добавлять в GitHub или пересылать
посторонним. Если Telegram уже отозвал сессию или сообщил AuthKeyDuplicated, код не может
восстановить отозванный ключ: останови лишние копии и получи новую строку этим способом.

## Управление

Кнопки: запуск, стоп, запрос сейчас, статус, интервал, наценка, блоки, SIM/eSIM.

- /markup 500 — прибавлять 500 в валюте каждой позиции.
- /percent 5 — прибавлять 5%; применяется перед фиксированной наценкой.
- /interval 15 — проверять раз в 15 минут.
- /status — состояние синхронизации и каждого поставщика.
- /sync — одна ручная проверка, в том числе при остановленном расписании.
  Ночное окно и FloodWait соблюдаются и при ручном запросе.
- /stop, /resume — выключить или включить расписание.
- /rejected — показать строки, которые не удалось надёжно распознать.
- /order iPhone 17, Samsung, Dyson — порядок создания новых блоков.
  Уже существующие посты Telegram нельзя переместить редактированием.
  Чтобы переместить блок вниз, выключи его и включи снова.

Список блоков заполняется после первого успешного чтения. Выключенный блок удаляется
из канала; повторное включение создаёт его внизу. Посты вне управляемого списка, включая
гарантию, не редактируются. Настройки из меню сохраняются и имеют приоритет над значениями
MARKUP, MARKUP_PERCENT, POLL_SECONDS и SIM_FILTER в Variables.

## Настройка разбора

Все переменные перечислены в .env.example. Например:

    MARKUP=500
    SIM_FILTER=all
    INCLUDE_BLOCKS=iPhone,Samsung,Dyson
    EXCLUDE_ITEMS=ремонт,разбит
    ALLOW_ACCESSORIES=false

Для точной выборки товаров INCLUDE_ITEMS задаёт подстроки названий, разделённые запятой.
EXCLUDE_ITEMS исключает совпадения. Пустой INCLUDE_BLOCKS/INCLUDE_ITEMS означает все
распознанные блоки/товары. ALLOW_ACCESSORIES=true оставляет аксессуары отдельным блоком.

Пример входа:

    iPhone 17
    eSIM
    🇺🇸 17 256GB Black — 58 800
    SIM
    🇮🇳 17 256GB Black — 62 900
    16 Pro 256 Natural CPO 🇺🇸 — 79 000

Фиксированная наценка 500 даст 59 300, 63 400 и 79 500. Пробелы в тысячах,
неразрывные пробелы, точка/запятая в дробной цене, ₽/$/€ поддерживаются.
Для корректного распределения строк без бренда поставщик должен указывать заголовок
модели/бренда. Перед публикацией незнакомого формата проверь /rejected.

Источник 2 включается через SUPPLIER_BOT_2, SOURCE_MODE_2, REQUEST_TEXT_2 и BUTTON_PATH_2.
Оба источника должны быть доступны аккаунту SESSION_STRING. Если их читают разные
пользовательские аккаунты, понадобятся отдельные сессии и дополнительная настройка.

## Проверки

GitHub Actions устанавливает зависимости на Python 3.12, проверяет синтаксис и запускает
python -m unittest discover -s tests -v.

Тесты не используют реальные Telegram-аккаунты и не отправляют сообщения. Они проверяют
разбор, наценку, фильтры, дедупликацию, лимиты, закрытие, таймауты, свежесть ответа, сохранение
состояния, повторный запуск, потерю ответа на публикацию, страницу входа и права управления.

Полная проверка конкретного поставщика требует его реальных прайсов и работающей сессии
на Railway. Успешные автоматические тесты не подтверждают права аккаунта, переменные
окружения и соответствие произвольного формата поставщика.
